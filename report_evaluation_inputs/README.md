# Real Report Evaluation Inputs

This directory contains copies of report-generation outputs produced by the realistic inference pipelines. Original files remain unchanged in their source directories.

## Directory structure

### `text_level/`

Each file contains 92 case-level test reports with `case_id`, `input`, `prediction`, and `reference` fields.

`autorg_input/` contains the realistic end-to-end pipeline results generated from AutoRG-Brain modality-wise predictions:

- `t5_small_test.json`
- `flan_t5_large_lora_test.json`
- `flan_t5_large_lora_pullloss_test.json`

`oracle_gt_input/` contains the corresponding oracle experiments generated from ground-truth modality-wise findings:

- `t5_small_test.json`
- `flan_t5_large_lora_test.json`
- `flan_t5_large_lora_pullloss_test.json`

The AutoRG-input results are the primary deployable-pipeline results. The GT-input results are oracle upper-bound analyses and must be labeled separately.

### `feature_level/`

Case-level reports generated by four feature-fusion methods. Each file contains 92 test cases under the top-level `results` field. A record uses `pred_report` and `reference_report` rather than `prediction` and `reference`.

- `mean_test.json` — non-trainable baseline
- `weighted_mean_test.json`
- `token_gated_test.json`
- `concat_projection_test.json`

### `vlm/`

Case-level Qwen2.5-VL reports with ground-truth references. Each file contains 92 test cases.

- `qwen25vl_zero_shot_test_with_gt.json`
- `qwen25vl_few_shot_test_with_gt.json`

### `single_modal/`

Modality-level AutoRG-Brain reports:

- `autorg_single_modal_test_with_gt.json` — 368 records: 92 cases x 4 modalities

This file must not be compared directly with the 92-case case-level files. It uses a different evaluation unit and modality-specific ground truth.

## Fair comparison sets

The main realistic case-level comparison may include the three AutoRG-input text-level models, all four feature-level models, and both VLM models. Align them by the same 92 `case_id` values and use the same case-level reference report. The three oracle GT-input text-level models may be evaluated with the same metrics but should be reported as a separate input-quality/upper-bound experiment.

For the primary feature-fusion ablation, use `mean_test.json` as the baseline.

Keep the single-modal results in a separate modality-level experiment unless the four modality reports are first converted into a predefined case-level baseline.
